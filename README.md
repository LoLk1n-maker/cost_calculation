# Расчёт плановой себестоимости изделия по КТД

Программная реализация функциональной модели (IDEF0) расчёта плановой себестоимости изделия машиностроительного производства по конструкторско-технологической документации: спецификации и технологическому маршруту.

Нормативный метод калькулирования — себестоимость определяется по техническим нормам до начала производства. Python + openpyxl, без внешних сервисов.

Подробнее в файле "Практика_Аблякимов.docx".

## Что делает

На входе — спецификация изделия (масса заготовки и детали по каждой позиции), технологический маршрут (операции, оборудование, нормы времени, разряды рабочих) и справочники предприятия (цены материалов и отходов, ставки машино-часа, тарифы по разрядам, страховые взносы, процент накладных).

На выходе — плановая калькуляция по статьям в Excel и тот же результат в JSON для передачи в смежные системы (1С, PDM).


## Архитектура = блоки IDEF0

Структура кода повторяет диаграмму декомпозиции A0: один модуль — один блок. Данные передаются по цепочке, каждый блок обогащает их.

| Модуль | Блок IDEF0 | Назначение |
|---|---|---|
| `parser_ai.py` | **A1** Анализ входных данных | Чтение спецификации и маршрута → структурированные данные |
| `reference.py` | **A2** Сопоставление со справочниками | Подстановка цен, тарифов, ставок и нормативов |
| `calculator.py` | **A3** Расчёт себестоимости | A31 материалы · A32 операции · A33 накладные · A34 агрегация |
| `report.py` | **A4** Формирование калькуляции | Excel по статьям калькуляции и JSON |
| `main.py` | — | Связывает цепочку A1 → A2 → A3 → A4 |
| `models.py` | — | Структуры данных: `Material`, `Operation`, `ProductData`, `CostResult` |

## Методика расчёта

**A31. Материальные затраты**

```
Зм = Σ (Mзаг · Цм − (Mзаг − Mдет) · Цотх)
```

Стоимость заготовки за вычетом возвратных отходов. Дополнительно считается коэффициент использования материала `Kим = ΣMдет / ΣMзаг`.

**A32. Затраты на технологические операции**

```
Зоп = Σ (tшк · Cраб · (1 + Cстрах) + tшк · Cмч)
```

По каждой операции: оплата труда по тарифу разряда со страховыми взносами плюс эксплуатация оборудования по ставке машино-часа.

**A33. Накладные расходы**

```
Знакл = (Зм + Зоп) · Kнакл
```

Процент от прямых затрат. База начисления задаётся в справочнике.

**A34. Итог**

```
Сполн = Зм + Зоп + Знакл
```

## Запуск

```bash
git clone <URL этого репозитория>
cd sebestoimost
pip install -r requirements.txt
python main.py
```

Нужен Python 3.9+. Результат появится в папке `output/`.

Чтобы посчитать своё изделие — замените строки в файлах `data/specification.xlsx`, `data/route.xlsx` и при необходимости дополните `data/spravochniki.json`. Если марка материала, оборудование или разряд отсутствуют в справочнике, блок A2 напечатает предупреждение, а соответствующая ставка будет принята равной нулю — калькуляция посчитается, но будет неполной.

## Исходные данные

| Файл | Содержание |
|---|---|
| `data/specification.xlsx` | Наименование · Марка · Масса заготовки, кг · Масса детали, кг |
| `data/route.xlsx` | Операция · Оборудование · Норма времени, ч · Разряд рабочего |
| `data/spravochniki.json` | Цены материалов и отходов, ставки машино-часа, тарифы по разрядам, `insurance_rate`, `overhead_rate` |

## Ограничения текущей версии

Это MVP функциональной модели, а не готовая система. Сознательно не реализовано:

- **Количество позиций.** Спецификация читается без графы «количество»: каждая строка считается одной деталью. Для реального BOM нужна графа с количеством и умножение материальных затрат на него.
- **Входные данные только структурированные.** Блок A1 читает Excel строго заданного формата. Разбор «сырых» документов (PDF чертежа, произвольная спецификация) предусмотрен как точка расширения `parse_with_llm()` в `parser_ai.py`, но в этой версии не подключён.
- **Упрощённая структура затрат.** Нет разделения накладных на цеховые, общезаводские и коммерческие, нет учёта подготовительно-заключительного времени, брака, инструмента и оснастки, транспортно-заготовительных расходов.
- **Накладные начисляются на все прямые затраты**, включая материалы. На многих предприятиях базой служит только оплата труда основных рабочих — это нужно согласовывать с учётной политикой.
- **Нет проверки корректности данных.** Не контролируется, что масса детали не больше массы заготовки, а нормы времени положительны.

## Дальнейшее развитие
